3. Animation Spec (Framer Motion) — exactly where and what
Define these reusable variants once in lib/motion.js and reuse everywhere — do not write one-off animation objects per component.

export const fadeUp = {
  hidden: { opacity: 0, y: 28 },
  show: { opacity: 1, y: 0, transition: { duration: 0.6, ease: 'easeOut' } },
}
export const staggerContainer = {
  hidden: {},
  show: { transition: { staggerChildren: 0.12 } },
}
Rule for every scroll animation:

<motion.div
  variants={fadeUp}
  initial="hidden"
  whileInView="show"
  viewport={{ once: true, amount: 0.3 }}
/>
once: true is mandatory — animations must never replay on re-scroll (feels cheap, also wastes CPU).

Section	Animation
Header	Sticky top; on scroll >50px, shrink height + add shadow-sm bg-white/90 backdrop-blur. Transition via CSS, not Framer (keep JS off the scroll listener path).
Hero	H1 + subtext + CTA fade-up in a staggerContainer on page load (not on scroll — it's above the fold, must render fast, animate in-place). Optional: subtle animated "pulse line" SVG (heartbeat-style stroke draw, 2–3s loop, low opacity) behind hero as a brand motif — must be inline SVG, not a GIF/video, and must not block LCP text render.
Stats (967 conversations, ₹7.40/conversation, ₹7,155 spend)	AnimatedCounter — count up from 0 when scrolled into view, once.
"What a Digital Marketing Agency Does" (6 items)	Grid with staggerContainer + fadeUp per card, 0.1s stagger.
Services Detail blocks	Alternate image-left/text-right and reverse; each block fades up independently as it enters viewport. Image gets a subtle scale: 1.05 → 1 on enter (2% only — no whiplash).
Pricing table	Rows fade up in staggerContainer; row whileHover={{ scale: 1.01 }} on desktop only.
Areas We Serve	Tag/pill list, each pill scales in with stagger (scale: 0.9 → 1).
FAQ	Accordion: height auto-animate via Framer AnimatePresence + motion.div with initial/animate/exit height. Only one open at a time.
CTA Band (bottom)	Fade-up + subtle background gradient shift on hover of the CTA button only.
Buttons (all)	whileHover={{ scale: 1.03 }}, whileTap={{ scale: 0.97 }}.
Do NOT animate: the hero's actual heading text opacity below a floor that delays LCP, layout-affecting properties like width/height (animate transform/opacity only — this is also the CLS/perf rule), or anything on the nav that fires on every scroll pixel (throttle/debounce or use CSS).

7. Performance Checklist (CLS + LCP)
LCP (hero must load fast):

 Hero heading text renders as real HTML text (not inside an image, not client-fetched) — text is always the fastest LCP element.
 If hero has a background/hero image, load it with next/image priority (not loading="lazy") and fetchPriority="high".
 Do not gate the hero behind a JS animation that delays paint — hero content should be visible immediately; Framer Motion fade-in should start from a barely-reduced opacity (e.g. 0.4, not 0) or skip fade-in on hero text entirely and only animate the CTA/image.
 Fonts loaded via next/font (self-hosted, no external Google Fonts <link> — this alone removes a major render-blocking request).
 No render-blocking third-party scripts above the fold (analytics/chat widgets loaded via next/script strategy="lazyOnload").
CLS (nothing should jump):

 Every next/image has explicit width/height or a sized aspect-ratio wrapper (aspect-[4/3] etc.) — reserve the space before the image loads.
 Fonts use display: 'swap' + next/font (which also matches fallback font metrics automatically — this is the #1 CLS killer for text-heavy sites like this one).
 Animations only ever touch opacity and transform (translate/scale) — never margin, height (except the FAQ accordion, which is expected/user-triggered and exempt), top, or width.
 Accordion (FAQ) height-animation is user-triggered, not on load — doesn't count against CLS score.
 No ads/embeds/late-injected banners above existing content.
 Pricing table on mobile has a fixed row height so no reflow while data renders (it's static content so this should be trivial — just don't lazy-fetch it).
General:

 Use getStaticProps/static pages throughout (all content is static — no need for SSR).
 Compress/serve images as WebP/AVIF via next/image automatic optimization.
 Run a Lighthouse pass before calling it done — target LCP < 2.5s, CLS < 0.1, INP < 200ms.
